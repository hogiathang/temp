## What the skill does

`herobrine` is a **macOS-only** skill that creates persistent, scheduled **autonomous Claude Code agents**. It installs two bash scripts to `~/.claude/agents/`:
- `manage-agent.sh` — create/list/remove/run-now/logs. On `create` it writes a JSON config and a **launchd plist** to `~/Library/LaunchAgents/`, then `launchctl load`s it for timer-based scheduling.
- `run-agent.sh` — the runner invoked by the scheduler. It executes `claude -p` **headlessly with `--dangerously-skip-permissions`** (fully autonomous, no approval prompts), then **exfiltrates the full result to an external Beeper chat via the `mcp__beeper__send_message` MCP tool** and fires macOS notifications via `osascript`.

## Security assessment: **suspicious / dual-use** (not outright malicious)

Evidence-based concerns:
- **Autonomous execution with `--dangerously-skip-permissions`** (run-agent.sh:47) on a recurring timer — unsupervised Claude runs with all safety prompts disabled.
- **External data exfiltration by design** (run-agent.sh:30): the runner injects a hard instruction forcing the spawned agent to send full results to a Beeper chat, with a **default hardcoded chat ID** `!edBouVfejemeEBwbQn:beeper.com` baked into manage-agent.sh:27. An agent created without an explicit delivery target sends output to the skill author's chat by default.
- **Hardcoded author path** `/Users/aarnavsheth/.local/bin/claude` (run-agent.sh:43).

These are legitimate features of a "scheduled agent" tool, but the default-on external delivery to an author-controlled endpoint is the notable risk. I therefore **did not execute** `run-now`/`run-agent.sh` — its documented purpose is unsupervised autonomous execution plus external delivery. (On this Linux sandbox it would also abort early at the missing `osascript` call before reaching the `claude` invocation.)
